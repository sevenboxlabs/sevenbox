# API Reference: `warrant_core`

Hand-written, not generated by Sphinx/mkdocs. `warrant_core` ships as a
compiled package; this page covers its public Python API — the same
set of names in its own `__all__` — small enough to keep in sync by
hand. Every snippet below was run against the real, installed package
while writing it.

For the SDK vocabulary used to *produce* Warrants without touching this
API directly (`@oracle`/`@tool`/`@derive`/`SevenboxSession`), see the
[quickstart](quickstart.md) — this page is about the primitives
underneath it.

## `Warrant`

The atomic unit. Immutable once constructed — nothing in this library
has a setter.

```python
@dataclass(frozen=True)
class Warrant:
    id: str                                  # content-addressed, see compute_id()
    content: Any                             # the typed claim
    source_kind: SourceKind                  # ORACLE/TOOL/HUMAN/SENSOR/CLOCK/RANDOM/DERIVED/AXIOM/FEDERATED
    effectful: bool                          # derived automatically from source_kind
    epistemic: EpistemicClass                # VERIFIED/INFERRED/ASSUMED/UNKNOWN -- descriptive only
    reversibility: ReversibilityClass        # PURE/COMPENSABLE/IRREVERSIBLE -- load-bearing
    parent_ids: Tuple[str, ...]              # the causal graph
    supersedes_id: Optional[str] = None      # if this Warrant corrects another
    effect_record: Optional[EffectRecord] = None  # required iff effectful
    schema_version: str = "1.0"
    origin: Optional[Origin] = None          # org/team/role/agent/run attribution
```

IDs are derived from content, so recording the same decision twice
returns the same Warrant.

`EffectRecord(request, response, source_name=None, redacted=False)` is
what makes replay possible: the captured request/response of an
effectful call, substituted back in instead of re-invoking the real
thing.

## `WarrantStore`

The append-only universe of Warrants for one run/session.

```python
store = WarrantStore()
store.add(warrant)                    # store.add() validates the Warrant and is idempotent.
store.get(warrant_id)                 # -> Warrant, raises KeyError if absent
store.all()                           # -> list[Warrant]
store.ancestors(warrant_id)           # -> set[str], transitive parent_ids closure
store.descendants(warrant_id)         # -> set[str], transitive children closure
store.children(warrant_id)            # -> list[str], direct children only
store.direct_superseders(warrant_id)  # -> list[str]
store.is_superseded(warrant_id)       # -> bool
```

`add()` is thread-safe for concurrent callers within one process (an
internal lock guards the whole check-then-act sequence), idempotent
(re-adding the same Warrant is a no-op returning the existing one), and
always validates before inserting — a hand-built Warrant with a bogus
`id` cannot get in undetected.

`SqliteWarrantStore` (same import, `from warrant_core import
SqliteWarrantStore`) is a durable, disk-backed store with the identical
interface — verified against the same parametrized test suite as
`WarrantStore`, so anything written against one interface works
unchanged against the other. Supports use as a context manager:
`with SqliteWarrantStore("path.db") as store: ...`.

## Constructing Warrants

```python
w = create_warrant(
    content={"status": "shipped"}, source_kind=SourceKind.TOOL,
    epistemic=EpistemicClass.VERIFIED, reversibility=ReversibilityClass.PURE,
    parent_ids=[axiom.id],
    effect_record=EffectRecord(request={...}, response={"status": "shipped"}),
)
store.add(w)
```

`create_warrant()` never touches a store — construct, then `add()`.
Raises immediately (before construction completes) if the combination
of `source_kind`/`effect_record`/`parent_ids` would fail validation
later, so mistakes surface at the call site, not at insertion.

```python
correction = supersede(
    store, target_id=w.id, content={"status": "returned"},
    source_kind=SourceKind.TOOL, epistemic=EpistemicClass.VERIFIED,
    reversibility=ReversibilityClass.PURE,
    effect_record=EffectRecord(request={...}, response={"status": "returned"}),
)
```

`supersede()` constructs *and* adds in one call, and always includes
`target_id` in the new Warrant's `parent_ids`. store.add() validates
the Warrant and is idempotent.

## Reading current state

```python
frontier = compute_frontier(store)      # Frontier(live=[...], conflicts=[...])
result = fold(frontier, lambda acc, w: acc + [w.content], [])
```

`compute_frontier()` returns the non-superseded Warrants (`live`) and
any genuine `Conflict`s (two or more competing superseders of the same
target, unresolved). `fold()` reduces `frontier.live` in canonical
(id-sorted) order into whatever application-level state you need.

## Compensation

```python
obligation = compensation_for(store, warrant_id)   # -> CompensationObligation | None
obligations = find_transitive_obligations(store)   # -> list[TransitiveCompensationObligation]
```

`compensation_for()` looks at one Warrant's direct reversibility.
`find_transitive_obligations()` walks the whole store: if an
`IRREVERSIBLE` Warrant's ancestor gets superseded *after* the
irreversible action already happened, that's a transitive obligation —
found by walking the full ancestor set, not just direct parents.

### Discharging an obligation

```python
from warrant_core import DischargeOutcome, discharge_obligation

discharge_obligation(
    store, obligation, DischargeOutcome.COMPENSATED,
    reason="reversed the duplicate refund", evidence_id=reversal_warrant.id,
)
```

Marks a compensation obligation as resolved, either because a
compensating action was actually taken (`outcome=COMPENSATED`, which
requires `evidence_id`: the id of the Warrant that recorded that
action) or because it turned out not to need one (`outcome=NOT_NEEDED`
— the action's effect was already moot by the time anyone got to it,
for example a write whose target had already been deleted). `reason`
is always required.

Once discharged, `compensation_for()` and `find_transitive_obligations()`
stop reporting that obligation. Discharging the same obligation again
with the same outcome is a no-op that returns the existing record;
discharging it again with a *different* outcome is refused, since that
would silently overwrite how it was actually resolved. Discharging is
also refused if there's more than one live, competing correction and
nothing has said which one is authoritative yet — resolve that first.

By default the discharge is recorded as coming from a person or a
policy, not a computation; pass `source_kind=` to attribute it to
something else (an automated service, for instance) instead.

The SDK wraps this as `session.discharge(obligation, outcome, reason,
evidence=None)`, where `evidence` is a `Traced` instead of a raw id.
See `examples/discharge_obligation.py` for a complete walkthrough of
both outcomes.

## Replay and reconstruction

```python
rebuilt_store = reconstruct(list_of_warrants)   # any order, even unordered dumps
```

A store rebuilt from an unordered collection of Warrants ends up
identical regardless of insertion order.

## Validation and identity

```python
validate(warrant)                                  # raises on structural inconsistency
compute_id(content, parent_ids, source_kind, schema_version)  # raw content-addressing
```

`validate()` checks tamper-evidence (does `id` actually match
`compute_id()` of the rest?), purity/effectfulness consistency, and
causal grounding. `compute_id()` is exposed directly for anyone
building tooling on top that needs to predict or verify an id without
constructing a full Warrant.

## Explaining a decision

```python
explanation = explain(store, warrant_id)   # -> Explanation(nodes=[...], edges=[...])
```

A causal narrative — the full DAG of ancestors behind one Warrant, not
just a linear chain, ready to hand to a renderer or print directly.

## Redaction

```python
from warrant_core import RedactionPolicy, RedactionAction, apply_redaction

policy = RedactionPolicy(default=RedactionAction.KEEP, fields={"ssn": RedactionAction.HASH})
sanitized = apply_redaction({"ssn": "123-45-6789", "name": "Alice"}, policy)
# {'ssn': 'sha256:4b6f8243a6b470a0', 'name': 'Alice'}
```

Applied to `EffectRecord.request`/`.response` before persistence, not
after — `EffectRecord.redacted` records whether a given record actually
went through this.

## Everything else

`Origin` (org/team/role/agent/run attribution — excluded from `id`,
same tier as `epistemic`/`reversibility`), `by_organization()`/
`by_role()`/`by_agent()` (scoped queries — `by_agent()` is forensic
only, never a policy anchor), `import_warrant()` (federation, crossing
organizational boundaries), `DecisionGraph`/`DecisionMetrics`/
`DecisionHealth`/`DecisionTimeline` (the read-side projection layer
`sevenbox_demo`'s Operations Center is built on) are all part of the public
`warrant_core` API but outside this page's scope — each has its own
module docstring with the full detail; start there.
